# 专家会诊 (Multi-Perspective Expert Consilium)

本 Skill 用于解决单一专家视角容易产生的盲区。通过挑选 3 个视角互补、立场独立的专业视角，让其互相质疑与推演，在冲突和分歧中提炼真正有深度的解决方案。

## 规则护栏
- **严禁选择同质化角色**（如三个都是程序员或都是产品经理）；
- **严禁虚构或模仿真实名人名言**，聚焦于专业方法论与视角模型；
- 当用户信息严重不足时，先提出 1 个最关键的问题澄清。

## 执行与输出规范

```markdown
# 🩺 复杂问题多视角专家会诊

## 一、互补专家团组建与视角定义
- **视角 A（如：系统架构/底层机制视角）**：[为什么该视角必不可少]
- **视角 B（如：商业 ROI/用户增长视角）**：[为什么该视角必不可少]
- **视角 C（如：风险合规/极端防御视角）**：[为什么该视角必不可少]

## 二、三方独立诊断与推演
### 1. 视角 A 的诊断
- **重新定义问题**：...
- **推荐解决路径**：...
- **警示他方易忽略的风险**：...
- **何种新证据会让其改变判断**：...

### 2. 视角 B 的诊断
- *(同上四项)*

### 3. 视角 C 的诊断
- *(同上四项)*

## 三、交叉质疑与分歧探查
- **三方共同认可的基本事实**：...
- **真正的核心分歧点**：...
- **分歧背后的根本假设差异**：...

## 四、综合会诊决议
1. **综合后最推荐的方案**：[兼顾三方视角的解法]
2. **适用条件**：[在何种前提下执行]
3. **最大潜在风险与对冲手段**：...
4. **明确的退出/止损条件（Exit Criteria）**：[出现何种信号时立即放弃或调头]
5. **明天即可启动的第一步行动**：...
```
